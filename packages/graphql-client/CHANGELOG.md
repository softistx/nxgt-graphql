## 0.5.0

## 0.4.0

### Minor Changes

- [#103](https://github.com/softistx/nxgt-graphql/pull/103) [`a7d46bb`](https://github.com/softistx/nxgt-graphql/commit/a7d46bbddb2a30f9906158370a793db1ac676d23) Thanks [@SteveGT96](https://github.com/SteveGT96)! - **Breaking: a subscription refused with an error status's event stream now rejects with the `ApiError` the stream carries**, instead of an `ApiStatusError` holding the stream's raw text. graphql-yoga refuses a subscription that way before it starts: a variable missing or of the wrong type (400), an error carrying `extensions.http.status` thrown before the subscription starts (that status), and APQ's `PersistedQueryNotFound` (404). The client reads the body's events with `@nxgt/httpyz`'s `createSseParser`, and the first `next` event whose data carries GraphQL `errors` becomes the same `ApiError` a refused JSON body gives: `status` is `extensions.http.status`, else the HTTP status; `httpStatus` is the response's status as it came; the 401 hook (`onUnauthenticated`) runs for a 401 as it does for JSON.
  
  APQ subscriptions on graphql-yoga now work with `useAPQ()`'s defaults: the 404 event stream is read as `PersistedQueryNotFound`, and the client connects once more with the query text, exactly once. `useAPQ({ responseConfig: { forceStatusCodeOk: true } })`, which 0.3 needed, is no longer required; it still works.
  
  Unchanged: an error status's event stream with no GraphQL errors in it (no `next` event, a result without `errors`, data that is not JSON) is still an `ApiStatusError(status)` whose `body` is the stream's raw text, and a refused body that cannot be read is still an `ApiStatusError(status)` with `body` undefined and the read error as `cause`. Queries and mutations are not affected.
  
  Migration: code that caught `ApiStatusError` for a refused subscription and parsed its `body` for `event: next` gets an `ApiError` now. Test it with `isApiError(error)` and read `error.errors`, `error.code` and `error.status` (or `error.httpStatus` for the HTTP status as it came) instead of parsing the text. If you set `forceStatusCodeOk` on graphql-yoga's `useAPQ` only for this client's subscriptions, you can remove it.

## 0.3.1

### Patch Changes

- [#101](https://github.com/softistx/nxgt-graphql/pull/101) [`10ed7e7`](https://github.com/softistx/nxgt-graphql/commit/10ed7e7296c6508502d8b61859941bf2d3ec8f6e) Thanks [@SteveGT96](https://github.com/SteveGT96)! - Requires `@nxgt/httpyz` ^0.4.1, so an install cannot pick 0.4.0. A reply whose body is cut off mid-read (the connection drops after the headers) is now `ApiUnavailableError('unreachable')`, its `cause` httpyz's `NetworkError` (message ending `reply body cut off`). Before, the runtime's raw `TypeError` escaped. It is not retried, since the reply came. A refused subscription is unchanged: when its body cannot be read it stays an `ApiStatusError` with its status, `body` undefined and the read error as `cause`.

## 0.3.0

### Minor Changes

- [#98](https://github.com/softistx/nxgt-graphql/pull/98) [`8067a48`](https://github.com/softistx/nxgt-graphql/commit/8067a48d290630e1c593eb46301c733ec7dfbf8d) Thanks [@SteveGT96](https://github.com/SteveGT96)! - Requires `@nxgt/httpyz` 0.4. A timeout that fires while the reply body is read now comes from httpyz itself.
  
  What changes for you: a body-read timeout is still `ApiUnavailableError('timeout')`, but its `cause` is now httpyz's `TimeoutError` (message `reply body not read within <n> ms`, with `timeout`, `method` and `path`, the signal's `DOMException` as its own `cause`) instead of the bare `DOMException`. Code that reads `error.cause` for a timeout sees the change; code that reads `reason` does not. An httpyz client of your own from before 0.4, passed as `http`, still gets `ApiUnavailableError('timeout')` for it.
  
  Unchanged: a subscription refused with an error status's event stream still rejects with `ApiStatusError`, its `body` the stream's raw text. The declarations now resolve fully under `moduleResolution: nodenext` too, so an unknown option to `createGraphQLClient` is a type error there, as it already was under `bundler`.

## 0.2.0

### Minor Changes

- [#95](https://github.com/softistx/nxgt-graphql/pull/95) [`690500c`](https://github.com/softistx/nxgt-graphql/commit/690500c0009e237619dfcccfaf06eaa3fd7e7316) Thanks [@SteveGT96](https://github.com/SteveGT96)! - **Breaking: an `ApiError`'s `status` is now a failure status unless `extensions.http.status` names another.** With no `extensions.http.status`, `status` is the HTTP status when it is 400 or above, else `400`; it used to be the HTTP status as it was, so a refusal sent on HTTP 200 (`200 {"errors":[…]}`, as graphql-yoga answers an error thrown in a resolver) read `status === 200` and now reads `400`. `httpStatus` keeps the HTTP status as it came (`200` there), and an `extensions.http.status` still wins on any HTTP status. A server answering its own caller with `error.status` no longer answers a refusal with 200; code that told a refusal on 200 apart by `status === 200` reads `httpStatus` instead. Nothing else about the errors changes: `onUnauthenticated` still runs for an extension's 401 or an HTTP 401. `ApiStatusError` gains `statusText`, the response's reason phrase (`Not Found`; `''` when the response had none, as over HTTP/2, or when a reply labelled JSON did not parse), set from the response for a query, a mutation, a batch and a refused subscription; built by hand, it takes it as an option beside `cause`, `new ApiStatusError(404, body, { statusText: 'Not Found' })`, the two- and three-argument forms unchanged (`ApiStatusErrorOptions`).
  
  `ApiErrorExtensions` is now an interface, so an application types the keys its API sends by declaration merging, `declare module '@nxgt/graphql-client' { interface ApiErrorExtensions { field?: string } }`: `error.extensions.field` and `error.errors[i].extensions?.field` are then `string | undefined`. Every other key stays `unknown`.
  
  `client.execute(document, variables?, options?)` runs a query or a mutation, whichever the document holds, exactly as `query` or `mutate` would (retries, deduplication, batching, cache, errors and the 401 hook included), for code that forwards documents it does not choose. Its options are `CallOptions` (`signal`, `headers`, `timeout`), what both take: a document's types do not say whether it is a query. A subscription rejects with `TypeError: execute() was given a subscription: use subscribe()`, before anything is sent.
  
  `createGraphQLClient`'s type follows its options: given a `cache`, it returns a `GraphQLClient<GraphQLCache>`, whose `client.cache` is read without a `!`; given none, a `GraphQLClient<undefined>`, whose `client.cache` is `undefined`, as it always was at runtime; given options typed `GraphQLClientOptions`, the `GraphQLClient` it returned before. `GraphQLClient` takes the cache's type as an optional parameter whose default is the former type, so `GraphQLClient`, `GraphQLProvider`'s `client`, `useClient()` and every hook take either kind of client unchanged. Nothing changes at runtime. One case that compiled before is now a type error: using `client.cache` on a client created without one (`client.cache!.read(…)`, `client.cache?.read(…)`, or `if (client.cache)`, which TypeScript now narrows to `never`); such code read a cache that was never there, and type the client `GraphQLClient` where it may be either. `createGraphQLClient` is overloaded for this: an option it does not take is now reported as `No overload matches this call`, the option still named.

## 0.1.0

### Minor Changes

- [#77](https://github.com/softistx/nxgt-graphql/pull/77) [`0bd813e`](https://github.com/softistx/nxgt-graphql/commit/0bd813e35ed45c5adf8ca071ed0da0d113bcec39) Thanks [@SteveGT96](https://github.com/SteveGT96)! - First release: `createGraphQLClient` over `@nxgt/httpyz` (its own, or yours as `{ http, path }`, from any copy of httpyz: its errors are recognised by name), with `query` and `mutate` on the client preset's documents (`TypedDocumentNode` or `TypedDocumentString`), typed errors (`ApiError`, `ApiStatusError`, `ApiUnavailableError`, `isApiError`), an awaitable `onUnauthenticated` hook, query retries (never a mutation), identical queries in flight shared (variables compared whatever their key order), persisted queries (`persisted: { mode: 'documentId' }` for the client preset's `persistedDocuments` hashes, or `{ mode: 'apq' }` for Automatic Persisted Queries), query batching (`batch: { max, wait }`, graphql-yoga's array batching), and `subscribe` over server-sent events (the GraphQL over SSE protocol's distinct connections mode, as graphql-yoga serves it): an `AsyncIterable` of each result's `data` with `close()`, connected on the first iteration, closed on every way out of the loop, never retried, reconnected, deduplicated or batched. An optional normalized cache for the browser, `cache: normalizedCache({ possibleTypes?, keys?, onError? })`: entities keyed by `__typename` and `id` (or `_id`, or `keys`), `__typename` added to the operations sent (the documents left untouched; with `documentId` persisted queries, the client preset's `addTypenameSelectionDocumentTransform` is required), a `fetchPolicy` per query (`cache-first`, `network-only`, `cache-only` throwing `CacheMissError` on a miss, `no-cache`), every query's and mutation's result written, and `client.cache` with `read`, `write` (all or nothing), `watch` (one call back per batch of changes, only when the result changed), `readFragment` and `watchFragment` (one entity through a fragment document), `evict`, `modify` (all or nothing, as `write`) and `reset`; field arguments keyed as the JSON sent (two `Date` variables are two entries); the cache holds JSON as the network sends it (a `Date` or a `Map` written throws a `TypeError`); a write made from a watch callback is applied at once and its watches called back after the current round; a watch callback or a `keys` function that throws goes to `onError` (default `console.error`), never thrown into a successful call and never ending the process, and an aborted signal wins over a cache hit. React 19 bindings on the new `@nxgt/graphql-client/react` subpath (`react` and `@types/react` `^19.0.0` as optional peers; the root entry never imports `react`): `GraphQLProvider` and `useClient` (throwing outside a provider); `useQuery(document, variables?, { skip, fetchPolicy, headers })` returning `{ data, error, loading, refetch }`, its variables compared by value (as the JSON sent: a `Date` by its ISO string), its request sent from an effect (none during a server render, which shows nothing from the cache: the browser renders it right after hydration) and aborted on unmount, on new variables and by StrictMode's second effect (an abort is never an `error`), kept current by the cache's `watch` when the client has a cache, `refetch()` asking the network and returning the data (rejecting at once and sending nothing while `skip` is true, or with an `AbortError` once kept past its variables or its component); `useMutation(document)` returning `[mutate, { data, error, loading, reset }]`, `mutate` returning the call's promise and recording the last call only; `useSubscription(document, variables?, { skip, headers, onData })` returning `{ data, error, active }`, closed on unmount and on new variables; `useFragment(fragment, ref, options?)` reading one entity through `readFragment` and `watchFragment` (a client with a cache required). No Suspense yet.
