'@nxgt/graphql-client': minor
---

First release: `createGraphQLClient` over `@nxgt/httpyz`, with `query` and `mutate` on the client preset's documents (`TypedDocumentNode` or `TypedDocumentString`), typed errors (`ApiError`, `ApiStatusError`, `ApiUnavailableError`, `isApiError`), an awaitable `onUnauthenticated` hook, query retries (never a mutation), identical queries in flight shared, persisted queries (`persisted: { mode: 'documentId' }` for the client preset's `persistedDocuments` hashes, or `{ mode: 'apq' }` for Automatic Persisted Queries), query batching (`batch: { max, wait }`, graphql-yoga's array batching), and `subscribe` over server-sent events (the GraphQL over SSE protocol's distinct connections mode, as graphql-yoga serves it): an `AsyncIterable` of each result's `data` with `close()`, connected on the first iteration, closed on every way out of the loop, never retried, reconnected, deduplicated or batched. An optional normalized cache for the browser, `cache: normalizedCache({ possibleTypes?, keys? })`: entities keyed by `__typename` and `id` (or `_id`, or `keys`), `__typename` added to the operations sent (the documents left untouched; with `documentId` persisted queries, the client preset's `addTypenameSelectionDocumentTransform` is required), a `fetchPolicy` per query (`cache-first`, `network-only`, `cache-only` throwing `CacheMissError` on a miss, `no-cache`), every query's and mutation's result written, and `client.cache` with `read`, `write` (all or nothing), `watch` (one call back per batch of changes, only when the result changed), `readFragment` and `watchFragment` (one entity through a fragment document), `evict`, `modify` and `reset`; a watch callback or a `keys` function that throws is reported, never thrown into a successful call, and an aborted signal wins over a cache hit.
