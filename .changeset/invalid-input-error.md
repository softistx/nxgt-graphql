Answering invalid input as one error: for an API that answers invalid input as one 400 error with a list of fields, `invalidInputError(issues, { translate })` builds that `GraphQLError`. Its `extensions` are `{ code: 'validation.errors.invalid-input', http: { status: 400 }, fields }`, each field `{ path, code, message, params? }` in the order given, its message `translate(code, params)` or the code itself without a translator. `params` is written only when it has a key, never `{}`. `fieldsError(code, issues, { translate, status, params })` does the same for a refusal of your own that names the fields at fault (a 409 conflict, say): `extensions` `{ code, params?, http?, fields }`. Both keep `GraphQLError`'s own options (`originalError`, `path`, `nodes`, …) but replace any `extensions` among them. `inputPath(['input', 'person', 'firstName'])` gives `person.firstName`, to map a Zod issue or a `BAD_USER_INPUT` issue to a field. Also exported: `INVALID_INPUT` and the types `FieldIssue`, `FieldError`, `IssueParams`, `Translate`, `InvalidInputOptions`, `FieldsErrorOptions`. What `withValidation`, `validated` and `badUserInput` raise is unchanged.
