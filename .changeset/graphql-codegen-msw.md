The first release: a graphql-codegen plugin that writes one typed msw 3 handler per named query and mutation, `mockUserQuery(resolver, options?)`, built on msw's `graphql.link(endpoint)`. The resolver is msw's own, its `variables` typed with the operation's variables type and its `data` with the result type, both imported from `typesImport` (the client preset's `graphql.ts`, or `typescript-operations`' file). Each handler checks its variables with `@nxgt/graphql-codegen-zod`'s `z<Operation>Variables` (`schemasImport`) before the resolver runs, and answers an invalid input without calling it: by default as one 400 error with a list of fields (`invalidInputError` from `@nxgt/graphql-validation`, a field per Zod issue, `translate: '<module>#<export>'` for the messages), with `invalidInput: 'bad-user-input'` as the `BAD_USER_INPUT` error `withValidation` raises, or with `invalidInput: '<module>#<export>'`, a function of yours returning `{ error, status }`. A `GraphQLError` the resolver throws is answered at its `extensions.http.status`; `errorResponse(error, { status })` builds the same answer. `endpoint` is required and overridable per handler (`options.endpoint`), beside msw's `once`. The generated file's runtime is the `./runtime` subpath: `mockOperation`, `invalidInputRefusal`, `badUserInputRefusal`, `fieldIssueOf`, `errorResponse`, `isGraphQLError`. Peers: `msw` `^3.0.3`, `graphql`, `zod`, `typescript`. Subscriptions, persisted queries and batching are on the roadmap.
